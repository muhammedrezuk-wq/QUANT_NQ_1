## 2026-08-27 — v2.3.0 (found during a full 304-atom audit, not assumed)

**`default_dial` was read from config and stored (`self._default_dial`),
but never used anywhere after v2.2.0 replaced the flat 50.0 default with
the `TRADING_HORIZON`-driven formula.** Any owner-configured value other
than 50.0 was silently ignored — masked because v2.2.0's own formula
(`100 - horizon_value(...)`) coincidentally equals 50.0 when the horizon
key itself is unapproved (its own internal default), exactly matching
`default_dial`'s own hardcoded default. A test (`test_ledger_activates_default_dial`)
already existed expecting `default_dial=60.0` to actually apply — it had
been failing, silently, since v2.2.0.

**Fix:** the fallback formula now anchors on `self._default_dial` instead
of a hardcoded 50, applying the SAME horizon-key-driven deviation the old
formula did: `default_dial + (MATCH_POINT - horizon_value(account, symbol))`.
At the horizon key's own neutral default (50 = `MATCH_POINT`) this is
byte-identical to the old formula, so behavior is unchanged for anyone
who never touched `default_dial` — only a genuinely configured non-50
value now actually takes effect, as documented and as the existing test
always expected. 9/9 tests passing, validator 0 violations.

**Related, not fixed here:** `shared/parameter_registry.py`'s
`approved_value()` cache and `shared/horizon_profile.py`'s `_rebuild_overrides()`
cache both had a separate staleness bug (fixed the same day, 2026-08-27,
in those files directly — see their own inline comments) where a process
switching between different registry files, or two callers passing
different fallbacks for the same unapproved parameter, could silently
read stale/wrong values. That bug was NOT the cause of this atom's
specific failure (traced and confirmed independently: `default_dial`
was simply never wired in) but affected five other atoms (454, 455, 456,
457, 463) whose own test suites surfaced it first. (458's own failure
that same day was unrelated -- a stale test predating the event bus's
V3.0 mailbox redesign, fixed separately in 458's own tests.)
