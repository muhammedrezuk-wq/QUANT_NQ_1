## 1.2.0 — 2026-08-27 (found during a full 304-atom audit, not assumed)

- **`ruling_math.py` had every one of its 8 functions defined twice,
  verbatim** (`_finite`, `_valid_points`, `interpolate`, `_contract_view`,
  `_declared_unknown`, `_read_number`, `_read_state`, `_side_applies`) --
  leftover from a bad merge during the campaign 450-901 extraction. Python
  silently kept only the second copy of each; the first was dead weight
  and a landmine for any future edit (fix the first copy, the second one
  Python actually calls stays broken). Both copies were identical today,
  so no behavior changed -- deleted the dead half.
- **`rules_store.py` had `_load_journal_tail` duplicated twice,
  `_journal` duplicated three times, and `_reject` duplicated three
  times** -- same bad-merge origin. `_reject` here was not just
  duplicated but **entirely dead**: the atom's own bound `_reject`
  method (defined directly on `Atom` in `atom.py`) is what
  `command_handlers.py` actually calls; these three copies in
  `rules_store.py` were never imported or called by anything. Confirmed
  by grep across the whole atom folder before deleting. Trimmed the
  `ruling_math` import line to the four names this file actually uses
  (`RESTORE_JOURNAL`, `ID_ENGINE`, `_valid_points`, `EIGHT_FIELDS`) --
  the old line imported eleven names the file never referenced.
- **`gate_runner.py` called `time.time()` on the fallback path of
  `_on_gate_passed` without ever importing `time`.** Untested because
  every existing test's `gate()` helper always sets `gated_at` to a
  valid float, so the fallback branch (`stamp is None`) never ran.
  Reproduced directly: a real `decision.gate.passed` payload missing
  `gated_at` raised `NameError: name 'time' is not defined` -- *after*
  `tilt.state` had already been published, so the tilt went out but the
  journal write crashed uncaught right after. Fixed by adding the
  missing import. New test `test_18_missing_gated_at_falls_back_to_now_no_crash`
  reproduces the exact omission and proves the fallback timestamp is a
  real `time.time()`, not just "didn't crash."
- **Blocking sqlite write on every approved decision.** `_on_gate_passed`
  fires on every `decision.gate.passed` event -- the hot path -- and
  ended by calling `atom._journal(...)` as a plain synchronous call
  (BEGIN IMMEDIATE, 8 inserts, COMMIT) directly inside the `async def`
  handler, no `asyncio.to_thread`. With `busy_timeout=10000` this could
  stall the event loop for up to 10 real seconds under store contention
  -- blocking every other handler sharing that loop, on a live trading
  path. Same pattern already fixed elsewhere in this project (701 and
  30 other atoms use `asyncio.to_thread` for exactly this). Now:
  `await asyncio.to_thread(atom._journal, ...)`. New test
  `test_19_journal_write_off_loop_thread` proves this empirically, not
  cosmetically: it makes the journal write artificially slow (0.3s) and
  races it against a concurrent 0.05s task via `asyncio.gather` --
  before the fix this ordering assertion would fail (the blocking call
  holds the only thread for the full 0.3s, so the concurrent task's
  timer can only fire after `_on_gate_passed` returns).
- **Not touched, and why:** `command_handlers._on_rule_command` has the
  same blocking-sqlite-in-async shape, but it fires only on owner-issued
  `tilt.rule.command` (a dashboard click, human-paced), not on every
  decision. Splitting its DB transaction into a thread-safe helper is a
  real refactor (the duplicate-check and the in-memory `_rules` update
  both need to stay correctly ordered around the thread boundary) and
  wasn't part of what this round's audit flagged. Documented here so it
  isn't forgotten, not fixed today to keep this round's diff to what was
  actually diagnosed.
- **`الشرح.md` had a stale hand-written section below the auto-generated
  card describing a different atom entirely** (`execution.manage.command`
  published, `decision.scored.state`/`platform.positions.state`
  subscribed, version `1.0.0`, a `score_threshold`/`tilt_fraction`/
  `lot_step` config) -- none of which match this atom since at least
  `1.1.0`. Corrected while already in this file for the version bump,
  rather than leaving a known-false section next to an honest one.
- 19/19 tests passing (17 pre-existing + 2 new), validator 0 violations.
