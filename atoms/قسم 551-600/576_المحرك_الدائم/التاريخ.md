- **2026-08-27 · v3.6.0 — naked-leg fix (found during a full 304-atom audit, not assumed).**
  `_try_key` opened a neutral pair via two sequential `await self._open(...)`
  calls (BUY then SELL). `_open` returned `None` on both success and on
  `HALT_BLOCKED` — so a halt landing in the real gap between the two legs
  left BUY open (real order, no stop-loss, protected only by the paired
  SELL) while SELL silently dropped, and the caller still emitted `OPENED`.
  Fixed: `_open` now returns `bool`; a blocked SELL after a real BUY is
  tracked by new sibling module `naked_leg.py` (same pattern as
  halt_gate.py/gate_window.py) and announced as `NAKED_LEG_HALT_BLOCKED`,
  never `OPENED`. `risk.kill_switch.reset_requested` now also triggers
  `naked_leg.complete_ready()`, which retries only the missing leg (never
  reopens the existing one). Naked-leg state persists across restart
  (`engine_persistence.py`) and surfaces in `health_check` (`DEGRADED` +
  `naked_legs`), never silently.
  **Same-pass fix, found reading `engine_persistence.py` against the live
  atom:** snapshot/restore referenced `atom._gate_window`, an attribute
  that has never existed (`atom._gate` — a `GateWindow`, `.decisions` — is
  the real object). The gate-467 window was silently never persisted
  across restart (snapshot always saved `{}`); now reads/writes
  `atom._gate.decisions`.
  **Also fixed:** `manifest.yaml` `subscribes:` was missing
